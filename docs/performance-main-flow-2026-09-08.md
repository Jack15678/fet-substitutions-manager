# 新增缺席主流程补测 · 2026-09-08

本次专门测试「新增並分析 → 核对涉及老师的课表 → 确认一个建议 → 刷新课表及剩余建议」。在学校 Linux 主机、原生产镜像的隔离容器中比较旧代码与待发布代码，正式数据库和正式服务未作修改；尚未上线。

## 测量口径

- 复用 9 月 7 日的学校数据库快照，以及包含 1,000 条历史代课记录的固定模拟学校。服务器、镜像及旧版提交详见 [原报告](performance-2026-09-07.md)。
- 每个场景先运行一次不计时的完整流程，再独立运行三次；每轮复制初始数据库、启动应用并正常登录，之后才开始计时。报告中位数并保存所有样本。
- 真正调用批量新增接口，包含验证、数据库写入和建议计算；核对课表按前端逻辑并行请求，确认后按前端逻辑顺序请求当前课表信息及有效课表。
- 学校回放日期为 2026-06-11、06-15、06-16，时钟固定在首日 00:00。单人场景有 6 堂待处理课，同日三人有 15 堂，三日期分别为 6、5、6 堂。为覆盖确认分支，选择具有可确认建议的教师；不代表所有教师或最坏情形。
- “总等待”是上述接口链的计时之和，包括确认一个建议及服务器返回的剩余建议，**不是完成全部待安排课程的耗时**；不包含用户思考、校内网络、Nginx 和浏览器绘制时间。没有进行并发用户压力测试。

## 正确性及发布判断

每轮检查创建个案数量、确认后修订号递增、已确认任务从待处理列表移除，并实际重复提交旧修订号，要求返回 409。比较优化前后完整业务响应：新增分析、候选排序及建议、核对课表、确认后的剩余任务、刷新结果与保存后的缺席信息；仅排除创建／更新／确认时间戳。

两组数据的三个场景均通过完整响应比较。两版合计运行 48 次完整流程（含每场景一次预热），全部通过上述检查。本地完整回归复测为 118 passed、8 skipped、20 subtests passed；跳过项仍为已有 HTTP 冒烟前置条件及私有考试夹具，不能算作通过。

学校生产镜像中复测 53 项调课测试、8 项日期范围测试，全部通过；仍有已有的 SQLite 连接 ResourceWarning 和弃用警告。首次回归命令遗漏挂载新版基准辅助脚本，导致两个引用 seed 的测试读取旧脚本而报缺表；补齐测试文件挂载后通过，未为此修改业务代码。测试结束时正式站点健康检查返回 `{"status":"ok"}`。

本轮没有继续改动业务逻辑：已有优化已让主流程整体加快，避免为小幅收益扩大改动范围。批量新增重复读取及确认时两次分析仍保留；后者用于提交前验证建议和提交后计算剩余任务，未省略正确性检查。

现有改动无数据库迁移、新依赖或跨请求缓存。主要需要防范的回归仍是跨日期课表遗漏、候选结果改变及撤销关联判断错误，不能承诺零风险。当前验证适用于上述样本与单用户接口调用，正式浏览器体验及多用户同时操作仍有验证边界。

## 复现

脚本为 [benchmark_absence_flow.py](../backend/benchmark_absence_flow.py)，复用原基准的隔离 HTTP 启动与登录代码。容器挂载方式沿用原报告，另挂载本脚本至 `/app/benchmark_absence_flow.py`。

旧版运行 `python benchmark_absence_flow.py --database /bench/school-snapshot.db --output /bench/results/flow-school-before.json --save-results /bench/results/flow-school-baseline.json`；优化版挂载两份待发布业务文件，使用 `--compare-results` 替换 `--save-results` 并写入独立计时文件。省略 `--database` 即运行模拟学校。

完整学校业务输出和数据库只保存在学校服务器隔离目录，未下载或加入仓库。

[原始计时样本](performance-main-flow-2026-09-08.json) 只包含汇总和时间，不包含学校业务数据。
